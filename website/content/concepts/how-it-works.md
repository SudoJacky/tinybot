# Tinybot 如何完成任务

你描述目标，模型判断如何处理，Tinybot 负责协调可用工具并把结果带回对话。理解这个过程，有助于分清“模型已经回复”和“任务已经完成”。

![Tinybot 的任务处理概念图：用户提出请求，模型按需调用工具，工具结果返回模型，最终形成答复。](/illustrations/agent-loop.webp)

*概念示意图，由 AI 生成；不代表应用界面或固定的执行顺序。*

## 01 · 你提供请求

请求包含任务说明，也可以附带文件或图片。当前会话、工作区和选中的 Skill 会影响这次任务得到的上下文。

例如“把会议记录中的待办整理成表格”，比“处理这个文件”更明确。

## 02 · 模型判断下一步

模型根据当前输入和可用能力，直接回答，或提出工具调用。Provider 是模型服务的连接，具体模型决定这次使用哪个模型处理请求。

模型服务可以在远端，也可以由你在本机部署。使用远端服务时，发送给模型的请求内容会离开本机；桌面应用不等于模型推理全部在本地进行。

## 03 · 工具执行并返回结果

需要读取文件、运行命令或调用已连接服务时，Tinybot 执行相应工具，把结果返回模型。模型可能据此继续调用工具，也可能已经有足够的信息完成回复。

这就是图中返回模型的环路。并非每条消息都需要工具，也不是每项任务只调用一次工具。工具失败时，应查看错误和任务最终状态。

## 04 · 你检查结果

最终结果可能是一段回复、一份文件或外部操作的结果。对照原始目标检查输出；有偏差时，在同一会话继续补充要求。

## 几个容易混淆的概念

| 概念 | 负责什么 |
| --- | --- |
| 模型 | 理解输入，判断下一步，生成内容 |
| 工具 | 执行具体动作并返回结果 |
| Skill | 提供处理某类任务的方法与约定 |
| 工作区 | 指定任务关联的目录和项目上下文 |
| Agent Graph | 把多步处理方式保存为可重复运行的流程 |
