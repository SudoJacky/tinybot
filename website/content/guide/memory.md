# 记忆管理

记忆保存可供后续会话使用的偏好与事实。它不同于完整聊天记录，也不同于正在进行的对话上下文。

## 查看记忆与适用范围

打开 **资源 → 记忆**，使用搜索和范围筛选定位条目。

| 范围 | 适合记录的内容 |
| --- | --- |
| 所有工作区（用户记忆） | 跨项目沿用的输出偏好、工作习惯 |
| 指定工作区 | 只适用于某个项目的事实、目录约定 |

<AppScreenshot id="memory-overview" />

新会话会取得当时适用的记忆快照。已有会话继续使用创建时的快照，所以修改后在旧会话里继续提问，不一定能验证最新记忆是否生效。

## 添加或编辑一条记忆

1. 点击 **添加记忆**，或选择已有条目的编辑操作。
2. 用一行写一条事实，选择用户范围或指定工作区。
3. 点击 **保存记忆**，确认列表中出现了保存后的内容。

例如，用户记忆可以写“汇报进度时先列出结果和未完成事项”；工作区记忆可以写“本项目的最终报告放在 reports/ 目录”。每条内容不能超过 2,000 字符。

<AppScreenshot id="memory-editor" />

手动添加或编辑的条目会标为 **用户维护**，自动整理不会修改或删除它。需要作为持续指令的行为约定，也可以放进 [自定义指令](./settings.md#自定义指令)。

## 删除与批量整理

使用单条删除，或进入 **多选** 后删除选中的条目。确认之前检查筛选范围，避免把其他工作区的记忆一起选中。

删除影响后续新会话使用的记忆，不会清除已有会话保存的快照，也不会删除原始聊天记录。未来的对话若再次提供类似信息，系统仍可能重新提取相似记忆。

## 自动提取与后台模型

符合条件的已完成对话会异步提取和整理长期记忆，并非每次都会产生新条目。页面内容未更新时可以刷新；需要排障时区分“没有可保留的事实”和“后台调用失败”。

**设置 → Provider 与模型 → 后台任务** 可为 Memory 指定模型，或跟随全局默认配置。后台提取与整理也会消耗 Token，分别列入 [用量统计](./token-usage.md)。

Team 内部任务不会自动触发长期记忆提取，但仍可使用既有的工作区记忆快照。任务报告应在 [团队结果](./teams.md#查看留言板、结果与用量) 中检查，不应以记忆条目是否增加来判断任务有没有完成。
